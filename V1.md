# v1: the simple version

The smallest game that's still fun: **gold, elixir, buildings, battles, studying that speeds it all up, and gems you can buy.**
Everything else from [GAMEPLAY.md](GAMEPLAY.md) comes later. All names and numbers are placeholders.

---

## 1. What's in

### Resources
| Resource | Source | Spent on |
|---|---|---|
| **Gold** | Gold mines, battle loot | Buildings, defenses |
| **Elixir** | Elixir collectors, battle loot | Troops, army buildings |
| **Knowledge** | Anki reviews only | Skipping timers |
| **Gems** | Real money; small free amounts (achievements, first clear of campaign levels) | Skipping timers, buying gold/elixir, the 3rd builder |

No dark elixir or ores in v1.

### Store (from day one)
- Gem packs (small to large).
- A one-time **starter pack** (cheap gems + resources + 3rd builder): the classic first purchase.
- Knowledge is never for sale.

### Buildings (about 10 types, each with ~3 levels)
| Building | Job |
|---|---|
| Town Hall | Its level caps everything else; stores a bit of both resources |
| Gold Mine / Elixir Collector | Produce over time; tap to collect |
| Gold Storage / Elixir Storage | Raise how much you can hold |
| Builder Hut | 2 builders = 2 upgrades at a time |
| Barracks | Trains troops with elixir |
| Army Camp | How many troops you can hold |
| Cannon | Defense: short range, hits ground troops |
| Archer Tower | Defense: long range |
| Walls | *Maybe v1; see decisions* |

Place buildings on a grid; drag to move them.

### Troops (3 types)
| Troop | Behavior |
|---|---|
| Fighter | Melee, attacks the nearest building |
| Archer | Ranged, attacks the nearest building |
| Brute | Slow, tanky, only targets defenses |

Troops cost elixir and need army camp space.

### Battles
- **Against computer-made bases, not other players** (no server needed yet):
  - a short **campaign** of hand-made bases (doubles as the tutorial),
  - **bandit camps**: generated bases scaled to your Town Hall, for farming loot.
- Deploy troops around the edge; they fight on their own; defenses shoot back.
- **No stars yet.** The battle ends when time runs out, your troops are all dead, or the base is destroyed.
  You see a destruction %, and **loot drops as you destroy storages and collectors**.
- **No trophies yet** (they come with PvP).

### Studying
- **Knowledge** per due review (anti-cheese rules from DESIGN.md §3). Spend it to skip timers.
- **Daily study bonus:** clear your due cards for the day to get a chest of gold and elixir.
- *Maybe:* **backlog siege**, where overdue cards attack your base (see decisions).

## 3. How it's built

| Piece | Choice |
|---|---|
| **Game core** | Plain TypeScript: rules, economy, timers, deterministic battle simulation. **No graphics code**, so the same code can run on a server later for PvP. |
| **Game screen** | **Phaser** (open source 2D engine, MIT license) drawing the core's state |
| **Anki add-on** | Thin Python layer: listens to reviews, saves the game locally, opens the game window |
| **Accounts + server** | **Supabase** (login, database). Needed from day one because of payments: purchases and the economy must live on the server, or people could edit their save file to give themselves gems, and purchases would be lost on reinstall. This also sets up PvP for v2. |
| **Payments** | A **merchant of record** (Paddle or Lemon Squeezy) via web checkout. They handle sales tax/VAT worldwide and refunds; fees are higher than plain Stripe (~5% vs ~3%) but it saves a solo dev a lot of tax/legal work. |
| **Save data** | On the server; a local cache so the game opens instantly and works briefly offline |
| **Dev loop** | Build and test the game as a normal web page first, with a fake "do a review" button; plug into Anki once it's fun |

## 4. Decisions

| # | Question | Recommendation |
|---|---|---|
| V1 | Battle computer bases first, PvP later? | Yes |
| V2 | Backlog siege in v1? | Yes. It's the only thing that makes your own defenses matter before PvP, and it reuses the battle code. |
| V3 | Walls in v1? | Next version. Troops pathing around and through walls is the fiddliest part of the battle code. |
| V4 | Top-down or isometric (the angled genre look)? | Top-down for v1, since it's simpler. The game core doesn't care, so we can switch the look later. |
| V5 | Build as a web page first, then put it in Anki? | Yes. It's faster to iterate, and I can test it here. |
| V6 | Gems and payments from day one? | **Decided: yes.** Means server + accounts in v1. |
| V7 | Payment provider | Merchant of record (Paddle or Lemon Squeezy) |
